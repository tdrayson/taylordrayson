# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a visitor-controllable dark mode (System / Light / Dark) that defaults to the OS preference and covers every surface plus the full data-visualisation palette.

**Architecture:** A `.dark` class on `<html>` redefines the `--color-*` design tokens in `resources/css/app.css`; because every component reads those tokens (utilities, inline styles, chart/map props), the whole site flips with near-zero component edits. A blocking inline script sets the class pre-paint to avoid a flash. A `useTheme` composable + `ThemeToggle` control drive the preference, persisted in `localStorage`.

**Tech Stack:** Tailwind CSS v4 (`@theme` / `@custom-variant`), Vue 3 + Inertia v3 (client-only, no SSR), Chart.js, maplibre-gl, Pest 4 browser tests.

## Global Constraints

- **Do NOT commit or push.** Taylor commits manually. Each task ends in a **Checkpoint** step: run the tests, report status, and stop for Taylor to commit. Never run `git add`/`git commit`/`git push`.
- **No arbitrary Tailwind bracket values** — use the standard token scale.
- **Split into small reusable components.** Comment Vue/JS functions, computeds, and non-obvious logic (opposite of the PHP minimal-comments rule).
- **a11y:** every hover has a mirrored `focus-visible` ring; specific `aria-label`s; `Icon.vue` is always `aria-hidden`.
- **Colours are consumed via `--color-*` tokens** — never hardcode a hex where a token exists.
- Branch: `feature/dark-mode`. One PR at the end.

### Task 4: `useTheme` composable

**Files:**
- Create: `resources/js/useTheme.js`

**Interfaces:**
- Produces:
  - `useTheme()` → `{ theme: Ref<'system'|'light'|'dark'>, resolved: ComputedRef<'light'|'dark'>, setTheme(value): void }`
  - `applyTheme(): void` — reads storage + system, toggles the `<html>` class, (re)binds the matchMedia listener. Safe to call once at app start.

- [ ] **Step 1: Write the composable**

Create `resources/js/useTheme.js`:
```js
import { ref, computed } from 'vue';

const STORAGE_KEY = 'theme';
const media = window.matchMedia('(prefers-color-scheme: dark)');

// Shared singleton state so every consumer (toggle, charts) sees the same value.
const theme = ref(readStored());
const systemDark = ref(media.matches);

// The stored preference; 'system' when unset or invalid.
function readStored() {
    const v = localStorage.getItem(STORAGE_KEY);
    return v === 'light' || v === 'dark' || v === 'system' ? v : 'system';
}

// The effective scheme after resolving 'system' against the OS setting.
const resolved = computed(() =>
    theme.value === 'system' ? (systemDark.value ? 'dark' : 'light') : theme.value,
);

// Reflect the resolved scheme onto <html> so the CSS .dark scope activates.
function applyClass() {
    document.documentElement.classList.toggle('dark', resolved.value === 'dark');
}

// Keep the resolved scheme in sync when the OS theme flips (only matters in 'system').
media.addEventListener('change', (e) => {
    systemDark.value = e.matches;
    applyClass();
});

// Persist a new preference and update the DOM immediately.
function setTheme(value) {
    theme.value = value;
    localStorage.setItem(STORAGE_KEY, value);
    applyClass();
}

// Called once at startup to align the class with stored state after hydration.
function applyTheme() {
    theme.value = readStored();
    systemDark.value = media.matches;
    applyClass();
}

export function useTheme() {
    return { theme, resolved, setTheme };
}

export { applyTheme };
```

and within `setup({ el, App, props, plugin })`, before `createApp(...)`:
